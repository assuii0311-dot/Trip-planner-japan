# 일본 — 현지인 중심의 장소를 어디서 가져오나

재방문 동네 19곳을 넣었다(닛포리·에비스·고엔지·구라마에·기요스미시라카와·
가구라자카·지유가오카·산겐자야·쓰키시마·료고쿠·아카사카·스가모 / 아타미·
가루이자와·지치부·오다와라·다카오산·가와사키·사와라). Wikivoyage 로는 동네당
0~18곳이 나온다. 대표 명소는 있어도 **현지인이 가는 식당·술집·가게**가 없다.
그것을 어디서 가져올지 조사한 결과다.

## 2. 두 단계로 나눈다 — 이렇게 된다

사용자가 제안한 대로다. **이름을 모으는 일**과 **내용을 채우는 일**을 나눈다.

### 1단계 — 이름 모으기 (사람)

타베로그·note·유튜브를 읽고 **이름만** 표에 적는다. 한 줄에 동네 slug 와
이름(한국어·일본어)이면 된다. 나머지 열은 비워도 된다.

```
city,name,nameEn,nameLocal,theme
ebisu,에비스 요코초,Ebisu Yokocho,恵比寿横丁,nightlife
koenji,다이이치 아사히,Daiichi Asahi,大一亭,food
```

이 단계는 사실(가게 이름)만 옮기는 것이라 어느 사이트를 봐도 된다.

### 2단계 — 내용 채우기 (스크립트 + 사람)

`node pipeline/import-manual.mjs japan` 이

1. 좌표를 찾는다 — Wikidata(명소) → OSM Nominatim(가게). 못 찾으면 넣지 않고 알린다.
2. 언어판 수로 유명도를 매긴다(Wikidata 에 있을 때).

그 뒤 사람이(지금은 내가) summary·why·caution·태그를 쓴다. 문장은 일본어
Wikipedia·상점가 사이트에서 **사실을 확인하고** 직접 쓴다. 타베로그 후기를
그대로 옮기지 않는다.

`node pipeline/collect.mjs japan` 이 이것을 자동 수집분과 합친다.

## 3. 이번에 확인한 것

- Nominatim 이 이 컨테이너에서 된다. "Ebisu Yokocho" → 恵比寿横丁 좌표.
- Overpass(OSM 질의 서버)는 두 미러 모두 막혀 있다. "이 동네 반경 500m 의
  이자카야 전부" 같은 자동 채우기는 지금은 못 한다. Nominatim 은 이름으로만 찾는다.
- 일본어 Wikipedia API 가 된다.
- 東京都オープンデータ 카탈로그는 403. 사람이 내려받아 넣어야 한다.
- 웹 검색·페이지 읽기가 된다. さんたつ(散歩の達人)·るるぶ·enjoytokyo·Hanako·
  aumo 같은 일본 산책 기사에서 **이름만** 뽑아 1단계 표를 채울 수 있다.
  기사 문장은 저장하지 않는다.
- Nominatim 은 비슷한 이름을 아무거나 돌려준다 — 大将 → 大醤(네리마),
  three → スリーエフ(편의점), REN → 특별양호노인홈 蔵前. 그래서
  `import-manual.mjs` 는 (1) 결과 이름이 찾던 이름과 같은 가게인지,
  (2) 동네 반경 안인지(반경의 두 배까지는 주소에 동네 이름이 있을 때만)
  확인한 것만 받는다. 동네 이름·업종 이름(もんじゃ, カフェ, 高円寺)만으로는
  받지 않는다.

## 5. 순서

1. 동네 19곳은 넣었다(Wikivoyage + Wikidata 반경). ✔
2. 동네마다 이름 8~12개를 1단계 표에 채운다. ✔ 12개 동네 108곳.
3. 2단계로 좌표를 찾고 설명을 쓴다. ✔ 82곳 들어감. 못 찾은 26곳은 위 목록 — 좌표만 있으면 된다.
4. 사용자가 타베로그·유튜브에서 본 이름을 CSV 에 더한다. 이름과 동네만 적어도
   좌표·설명은 같은 순서로 채운다.
